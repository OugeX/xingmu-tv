# 播放源导入方式（遥控器不能打字，这是主设计矛盾）

结论：**遥控器输入只做兜底，主路径是「手机扫码 → 局域网网页里粘贴/上传」。**

## 1. 四种导入方式（按优先级）

| 级别 | 方式 | 用户动作 | 打字量 | 依赖 |
| --- | --- | --- | --- | --- |
| **P0 一键目录** | 内置源目录（预置 bfzy1、备用站、直播源） | 上下选中 → OK | 0 | 无（离线内置） |
| **P1 手机扫码**（主路径） | TV 显示二维码 → 手机扫码开网页 → 粘贴 JSON / 传文件 / 填 URL → 点提交，TV 实时收 | 手机打字（手机有键盘） | 手机上随便打 | 手机与 TV 同一 WiFi |
| **P2 配对码** | TV 显示 6 位数字码，手机打开 `http://<tv-ip>:8088` 输入该码配对，再提交 | 手机上点 | 极简 | 同上 |
| **P3 U 盘 / 文件选择器** | 插 U 盘 → 自动弹出「发现 3 个源文件，导入？」；或系统文件选择器（SAF）手动挑 | 点两下 | 0 | U 盘 |
| **P4 遥控器输入**（兜底） | 分组键盘 + 域名补全 + 历史记录 + 短链输入 | 遥控器打字 | 多 | 仅当以上都不可用 |

## 2. 手机扫码导入的技术实现

1. TV 端启动**局域网 HTTP 服务**（`ServerSocket` 自实现，端口 8088，随机 fallback）；只在导入页打开时才启动，退出即关（省电、减小攻击面）。
2. 二维码内容 = `http://<局域网IP>:8088/i/<一次性token>`；token 有效期 5 分钟，一次有效。
3. 手机网页（TV 端内置的单页 HTML，无外网依赖）提供三个入口：
   - **粘贴 JSON**（textarea，支持直接贴 `tvapp.source.v1` 或裸 MacCMS 地址）
   - **上传文件**（`.json` / `.m3u` / `.txt`，multipart）
   - **只填一个 URL**（自动识别 MacCMS / m3u / bundle，自动补全 `ac=list` 探测）
4. 提交后 TV 端收到 → 走同一套 L0–L4 校验 → 成功弹「已导入 N 个源（M 个频道）」→ 自动回到源列表并高亮新源；失败按 15 个错误码给中文原因。
5. 安全：仅绑定局域网网卡、token 校验、5 分钟过期、单次导入后关闭服务、拒绝超过 2MB 的文件、Content-Type 白名单。

## 3. 配对码（给不想扫码的人）

TV 显示 `192.168.1.23:8088` + 6 位码 `482913`；手机浏览器输地址后填码即可，无需扫二维码。适合老式电视/二维码被反光看不清的场景。

## 4. 遥控器输入（兜底也做好）

- **分组键盘**：数字行 / 字母行 / 常用符号，`OK` 选字，`BACK` 退格；只显示 URL 需要的字符（`: / . - _ ? = &`）。
- **域名补全**：输入 `macapi1` 自动补 `.com`；输入 `bfzy` 弹出历史候选。
- **历史与剪贴板**：最近 10 条成功导入的地址一键复用（绝大多数用户导入的是同一个源）。
- **短码输入**：如果用户在手机端网页点「生成 6 位导入码」，TV 端只需输 6 位数字，内容由云端/对端 URL 提供 —— 仅用于团队自建源分发，不做公开服务。

## 5. 导入之后

- 源列表逐条显示：名称 / 类型 / 状态灯 / 延迟 / 优先级 / 频道数。
- 支持「测试连通」「启用停用」「上移下移（priority 数值小优先）」「删除」「重新校验」。
- bundle 源支持「检查更新」（`refreshIntervalHour`），有更新时提示「源合集有更新，是否更新？」。

## 6. 验收

| 项 | 标准 |
| --- | --- |
| 扫码链路 | 手机扫码 → 粘贴 JSON → TV 3 秒内收到并导入成功 |
| 配对码 | 输 6 位码可完成导入；错误码提示明确 |
| U 盘 | 插入后 2 秒内发现 `.json/.m3u` 并提示 |
| 兜底键盘 | 纯遥控器能完成一次 MacCMS 地址导入 |
| 安全 | 导入页退出后端口关闭；token 过期后链接失效 |
| 包体 | 二维码库用 `zxing-core`（≈500KB），不引 camera 模块（TV 端不扫码，只显示） |
