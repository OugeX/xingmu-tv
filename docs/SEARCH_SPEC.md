# 搜索规格：语音 / 首拼 / 结果布局

## 1. 语音输入：三层降级，不做假按钮

| 层 | 方案 | 条件 | 包体 |
| --- | --- | --- | --- |
| **P0 系统识别** | `RecognizerIntent.ACTION_RECOGNIZE_SPEECH`（`zh-CN`，free-form），系统弹窗收音 | 设备有 Google/讯飞等系统识别服务（部分电视盒子自带） | 0 |
| **P1 自建 ASR** | 用户在设置里填自己的 ASR 接口（OpenAI 兼容 `/audio/transcriptions` 或讯飞 RTASR endpoint + key）；按住 OK 录 16k/16bit 单声道 PCM，松手上传取文本 | 有网 + 用户填了 key | 0（纯 HTTP，不引 SDK） |
| **P2 无可用** | 语音按钮**直接隐藏**，提示「本机不支持语音，可用首拼搜索」 | 以上都不可用 | 0 |

- 不做：常驻监听、后台录音、上传到我们自己的服务器（没有服务器）。
- 权限只申请 `RECORD_AUDIO`，且仅在按住时录音；松手立即停止并释放。
- 语音识别结果落到输入框后仍走同一套搜索链路（可编辑再搜）。

## 2. 首拼 / 全拼搜索（本地索引，不依赖源站）

MacCMS 的 `wd` 参数只做中文/字符串匹配，**拼音必须本地做**。

### 2.1 已生成的资产

| 文件 | 内容 | 体积 |
| --- | --- | --- |
| `assets/pinyin_initials.json` | 6763 个汉字 → 首字母集合（多音字给全部候选，如 `长→"cz"`、`繁→"fp"`） | 69KB |
| `assets/pinyin_full.json` | 6763 个汉字 → 全拼候选（`长→"chang\|zhang"`） | 91KB |

自检通过：`流浪地球→lldq`、`漫长的季节→mcdjj/mzdjj`、`庆余年→qyn`、`长安三万里→caswl/zaswl`。

### 2.2 索引

- 表：Room + **FTS4**（minSdk 21 的 SQLite 没有 FTS5），列 = `title, initials, fullpinyin, year, typeId, poster`。
- 每条作品写入时，用首字母集合做变体展开（每字最多取 2 个候选，整条最多 64 个变体），空格分隔写入 `initials` 列。
- 查询：`SELECT ... FROM search_index WHERE initials MATCH 'lldq*'`，前缀匹配天然支持边打边搜。
- 索引覆盖：热榜 + 各分类首页前 300 条 + 用户浏览/收藏过的作品，目标 5000–8000 条；建索引 ≤300ms，占用 ≤2MB（存 SQLite，不占内存）。

### 2.3 混合检索策略

| 输入类型 | 行为 |
| --- | --- |
| 纯字母（如 `lldj`） | **本地首拼索引即时出结果（<50ms）** + 并行把原串发给 API `wd`（部分源支持英文名） |
| 中文（如 `流浪`） | 走 API `wd`（多源并发 3、单源 3.5s、4.5s 硬截止） |
| 数字/混合 | 先本地模糊，再 API |
| 首拼有候选 | 输入框下弹出候选作品名（最多 6 条），D-pad 上下选、OK 直接进详情 |

## 3. 结果页布局（做了三处优化）

```
┌ 搜索：「lldj」     [🎤 语音]  [清空]                                   ┐
├ Tabs: 全部 · 电影 · 剧集 · 动漫 · 综艺 · 海外 · 直播                    │
├ 候选：流浪地球2 · 流浪地球 · 流浪地球3 …（首拼命中提示）                │
├ 网格 6 列（720p 5 列）：                                                 │
│   [海报]  [海报]  [海报]  [海报]  [海报]  [海报]                        │
│   流浪地球2   流浪地球    流浪地球3   …                                  │
│   2026·8.7   2019·8.4   2027·—                                          │
│   3源可用     2源可用     1源可用                                        │
└ 底部：共 128 个结果 · 已加载 24                                          ┘
```

优化点：

1. **分段 Tab**：默认「全部」，但类型 Tab 显示各类命中数（`电影 42`），避免在混合结果里翻找。
2. **命中高亮 + 来源提示**：标题里命中的字用主色加粗；首拼命中的卡片多一行小字「lldj · 流浪地球2」提示为什么被匹配到。
3. **同片合并**：跨源同名片合并成一张卡，角标「N 源可用」，点进去在详情页换源，而不是结果里出现 5 个重复条目。
4. **排序**：精确匹配 > 前缀匹配 > 包含匹配；同分按 `评分 → 年份 → 源数量`。
5. **渐进加载**：首屏只渲染 24 项，滚到底再取下一页；骨架屏 6 个灰块（C 模式用一行「加载中…」）。
6. **空态**：显示热词 chips（来自本地热榜）+「换个词试试」。
7. **历史**：最近 10 条搜索词，长按可删；输入框聚焦即展开。

## 4. 键盘（电视遥控器友好）

- 三态：数字行 / T9 九宫格（长按出字母候选）/ 完整 QWERTY（折叠在「更多」里）。
- 纯字母输入时**边打边搜**：300ms 防抖，首拼命中先渲染，API 结果回来再合并。
- `BACK` 逐字删除；清空按钮；`OK` 直接搜。

## 5. 性能预算

| 指标 | 目标 |
| --- | --- |
| 首拼本地结果 | ≤50ms（同步查询，走 IO 线程后再上屏） |
| 首屏可见结果 | ≤300ms（先渲染本地命中） |
| API 聚合 | 并发 3，单源 3.5s，硬截止 4.5s，超时源标灰不阻塞 |
| 索引构建 | 冷启动 ≤300ms，不超过 2MB |
| 内存 | 结果页列表复用，图片 320×450 请求，不缓存原图 |

## 6. 验收

| 项 | 标准 |
| --- | --- |
| 语音 | 有系统识别时可用；无则按钮隐藏并给提示；录音仅在按住期间 |
| 首拼 | `lldq`、`mcdjj`、`qyn` 能命中对应作品；多音字两种拼法都命中 |
| 结果布局 | Tab 计数正确、同片合并角标正确、高亮正确、滚动分页 |
| 性能 | 首拼 ≤50ms、首屏 ≤300ms、超时源不阻塞 |
