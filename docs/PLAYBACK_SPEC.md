# 播放与直播规格（回答 7 个产品问题，engineer 按此实现）

## 1. 解码引擎：用什么解、会不会卡

**不用自研解码器**，走 Android 原生媒体栈：

| 层 | 实现 | 说明 |
| --- | --- | --- |
| 播放内核 | Media3 ExoPlayer 1.5.1 | 负责解封装、HLS 分片调度、音画同步、seek |
| 硬解 | 系统 `MediaCodec`（SoC 自带 VPU：Amlogic / Rockchip / 海思 / MTK） | 默认路径，1080p H.264 功耗与发热最低 |
| 软解 | 平台软件解码器（`c2.android.avc.decoder` 等） | `setEnableDecoderFallback(true)` 自动回退，**不打包 FFmpeg 扩展**（+14MB 包体，1GB 盒子跑 1080p 软解必卡） |
| 输出 | `SurfaceView` 直出 | 比 TextureView 少一次 GPU 纹理拷贝 |

### 防卡的五道保险

1. **上限压死**：默认 `maxVideoSize 1920×1080`、`maxVideoFrameRate 30`、`maxVideoBitrate 6Mbps`、优先 H.264 —— 老 SoC 解 1080p60 或 HEVC 就是会花屏掉帧，直接不选。
2. **能力探测**：首次启动探测 HEVC/4K 支持度并缓存；源只有 HEVC 而设备不支持时，明确提示「当前设备不支持该编码，请切换线路」，不去盲目软解。
3. **掉帧自救**：运行时采样 `videoFormatRenderer` 掉帧率，30 秒窗口内掉帧 >20% 自动降一档清晰度并 toast「网络/性能不足，已切 720p」。
4. **缓冲确定性**：直播 min 6s / max 15s / 8MB，点播 min 15s / max 30s / 12MB，`setBackBuffer` 直播 0 —— 内存不随播放时长增长。
5. **首帧优先**：`bufferForPlayback 1.5s(直播) / 2.5s(点播)`，冷启动 ≤1.5s 出 UI、≤2.5s 出画面。

> 能力边界：盒子本身的 VPU 决定天花板。1GB / RK3229 级别设备能做到 1080p30 H.264 流畅；4K 源在该类设备上会被降档到 1080p 播放，这是硬件限制，不是引擎问题。

## 2. 频道列表与切换

| 场景 | 交互 |
| --- | --- |
| 进入直播页 | 左侧 320dp 频道列表（分组：央视 / 卫视 / 地方 / 港澳台 / 其他），右侧立即播放上次频道 |
| 上下切台 | `DPAD_UP/DOWN` 在列表内移动即预览切台（800ms 防抖，避免连按狂切） |
| 快速切台 | `CH+ / CH-`（遥控器按键映射 `KEYCODE_CHANNEL_UP/DOWN`）直接上一个/下一个频道 |
| 数字直达 | 遥控器数字键输入台号，1.5s 内确认即跳转（如 `0 1` → CCTV-1） |
| 全屏浮层 | `MENU` 呼出半透明频道九宫格，不退出播放即可换台 |
| 收藏/最近 | 列表顶部固定「最近观看」+「收藏」两个分组 |

切台失败处理：该频道按 priority 依次尝试备用源（最多 3 条），全失败 → 提示「该频道暂不可用」+ 自动跳到下一个可用频道，**不黑屏卡死**。

## 3. 频道介绍信息

频道详情面板（列表项右侧 / 播放中 `INFO` 键呼出）：

| 字段 | 来源 |
| --- | --- |
| 频道名、台标、分组 | `assets/live_seed.json`（内置）+ 用户导入 m3u 的 `tvg-name/tvg-logo/group-title` |
| 分辨率、码率、编码 | 起播后从 `TracksInfo` 实时读取 |
| 备用线路数、当前线路延迟 | 播放心跳测速 |
| 频道简介 | 内置字段 `desc`（央视/卫视预置一句话简介） |
| **节目单 EPG** | 源配置 `epgUrls`（XMLTV），解析后显示「正在播 / 下一档 + 进度条」；无 EPG 时显示「暂无节目单」而不是空白 |

EPG 刷新：进入直播页拉一次 + 每 30 分钟后台刷一次，解析结果落本地缓存（离线可看）。

## 4. 倍速

- 点播：`0.75 / 1.0 / 1.25 / 1.5 / 2.0`（`PlaybackParameters(speed, pitch=1f)`，音调不变）。
- 直播：**不给倍速**（HLS live 拉伸会导致音画漂移和缓冲累积），菜单里该项置灰并提示原因。
- 倍速只对当前播放生效，不记忆到下一次；退出恢复 1.0。

## 5. 快进 / 快退

| 操作 | 行为 |
| --- | --- |
| 单击 `LEFT / RIGHT` | −10s / +10s（`SeekParameters.CLOSEST_SYNC`，1s 分片下几乎瞬时） |
| 长按 `LEFT / RIGHT` | 连续 seek，每 200ms 累加 10s，松手落定 |
| HUD 进度条 | 聚焦后可左右拖动预览，确认才 seek |
| 直播 | 仅在 DVR 窗口内可回退（HLS 带 `EXT-X-MEDIA-SEQUENCE` 的保留时长），超出窗口时按钮置灰 + 提示「该频道不支持回看」 |

## 6. 选清晰度

一个「画质 / 线路」面板，三层能力合并：

1. **HLS 多码率**：master playlist 有多档时，提供 `自动 / 1080p / 720p / 480p`，只改 `trackSelector` 的 `maxVideoSize/maxVideoBitrate`，**不重建播放器**，无黑屏。
2. **多线路**：MacCMS `vod_play_from` 按 `$$$` 拆（如 `bfzym3u8$$$bfzy`），面板按线路列出，切换时保留播放进度。
3. **多站同名片**：聚合搜索命中的同名片按源列出（「暴风源 / 备用源A」），一键换源续播。

面板每行显示：线路名 + 实测分辨率 + 延迟 ms + 可用状态灯。选择结果持久化（SharedPreferences），下次同名剧优先用上次成功的线路。

## 7. 采集源广告：能关到什么程度

**结论先说**：网页广告 100% 没有；片头贴片广告能跳过大部分但不能保证 100%，取决于源的编码方式。分三层处理：

| 层 | 手段 | 效果 |
| --- | --- | --- |
| L1 站点广告 | App 只调 JSON API，不加载任何网页/H5 | 弹窗、浮层、插屏、跳转广告**根本不存在** |
| L2 请求拦截 | OkHttp 拦截器 + 域名黑名单（`ad.`/`ads.`/`/ad/`/`/ads/`/`adv.`/统计域名），命中直接返回空响应并记日志 | 独立广告分片、广告图片、统计上报全部拦死 |
| L3 贴片跳过 | 每源可配 `skipIntroSeconds`（默认 0，可在源管理页改）；playlist 含 `#EXT-X-CUE-OUT` / `#EXT-X-DISCONTINUITY` 时按 cue 自动跳过 | 固定贴片秒数的源可全自动跳过；无 cue 且与正片同流的只能硬跳 N 秒 |

- 广告黑名单可在「播放源管理 → 高级」里编辑，支持导入自己的规则。
- **不承诺 100% 去广告**：贴片与正片混编在同一条 m3u8、且没有 cue 标记时，任何客户端都只能盲跳，跳多了会切掉正片开头，所以默认保守（仅按源配置的秒数跳）。
- 源站若整段用转码器把广告烧进正片，属于内容本身，客户端无法去除 —— 这种源会被标记「含烧录广告」，在选择源时优先级降权。

## 8. 交付验收（对应 t4 / t5）

| 项 | 验收 |
| --- | --- |
| 解码 | 1080p H.264 硬解起播 ≤2.5s；拔掉硬解（模拟）能回退不崩 |
| 频道 | 列表分组正确、CH+/CH- 切台、数字直达、失败自动跳下一个 |
| EPG | 有 epgUrls 时显示节目单；无则显示「暂无节目单」 |
| 倍速 | 5 档可切，音调不变；直播项置灰 |
| seek | 单击 ±10s、长按连续、直播超窗置灰 |
| 清晰度 | 多码率/多线路/多源三种切换都不断播 |
| 广告 | 拦截器命中日志可查；skipIntro 生效；面板可编辑规则 |
